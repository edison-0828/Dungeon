# 2026-08-31

## 代码审查：SPD v3.3.8 魔改分支

项目是 Shattered Pixel Dungeon v3.3.8 的个人魔改（基线 commit 7b8b845）。
改动面：24 个已有文件 + 新增 BeginnerAid.java + 10 个测试文件 + GitHub Actions CI。
冒烟验证：`./gradlew :core:test` 通过，561 个用例全绿（CombatFormulaTest 233、LevelGenerationTest 249 为主力）。

### 待修问题（按优先级）

**P0-1 BeginnerAid 数值削弱漏了 isNovice 开关**
`scaleEnemyDamage()` 与 `enemyAccuracyFactor()` 两个函数都没调用 `isNovice()`，
导致敌人伤害 ×0.85、命中 ×0.75（叠加约 ×0.64）永久生效，与类 Javadoc
「仅在首次击败 Goo 前生效」矛盾。其余入口（Goo 血量、额外口粮、mob 密度、hint）都正确加了开关。

**P0-2 Hero.STARTING_HP = 200（原版 20）**
10 倍血池使治疗药水、吸血、饥饿伤害等整套数值体系失衡，30 级上限从 165 → 345。

**P0-3 Hero.updateHT 旧存档补丁可被利用刷血**
`else if (curHT > 0 && HT - curHT >= 50 && HP > 0) HP += HT - curHT;`
RingOfMight 装备/升级/卸下都调 updateHT(false)（RingOfMight.java:42/52/74），
力量戒指的 HT 倍率会让差值超过 50 → 反复穿脱戒指即可回满血。
版本迁移应走 Dungeon.version，不要用运行时启发式。

**P1-1 SPDAction.ensureWalkKeys() 会摧毁用户自定义绑定**
addHardBinding 优先级最高 + bindings.put() 强行覆盖 + setAllBindings 持久化，
用户无法把 WASD 映射到其他动作。应改为仅在绑定缺失时补默认（putIfAbsent 语义）。

**P1-2 BeginnerAid.shown 不存档**
static HashSet，resetForRun() 只在 Dungeon.init() 调用；读档走 loadGame() 不过 init()，
导致读档后提示全部重弹。应打进 bundle。

**P2 其他**
- `isHostileDamage()` 在伤害热路径用反射遍历 getEnclosingClass()，应改为伤害源携带归属引用。
- BeginnerAid 零测试覆盖；且 HeadlessDungeon 里 Badges.reset() 只清 local 不清 global，
  空沙箱下 isNovice() 恒为 true，所以 LevelGenerationTest 的 1-4 层一直跑在「新手路径」（mob-1），
  正常分支从未被覆盖。应在 HeadlessDungeon 显式固定新手状态并做参数化。
- Goo 三重削弱叠加（85 血 + 英雄 200 血 + 0.64 输出）过头，boss 战教学价值丧失。

### 已修好的真实 bug（勿回退）

- `Level.buildOpenSpaceMap()`：抽出方法并在 build() 末尾调用，修复 solid 与 openSpace 不一致
  （原本会让大型怪被放进墙里）。LastLevel 因之后又收紧 solid，需手动补调。
- `Generator` WEP_T3.probs 原版误用 WEP_T1.defaultProbs，已修正为 WEP_T3.defaultProbs。
- Goo 描述补充「水中回血 / 蓄力要躲」的战术提示，中英双语同步。

### 值得保留的资产

`HeadlessDungeon` 测试基础设施质量很高：临时沙箱隔离存档、preferences 目录刻意避开
libGDX 默认 `.prefs/`、注释解释了每个决策的 why。LevelGenerationTest 测的是真正的不变量
（出口可达、边界封闭、种子确定性、无物品被封在实心岩里），不是凑覆盖率的快餐测试。
CI 排除 :android / :ios 并注明了理由。

## 同类对标分析（第二轮）

### 上游基线与竞品现状（2026-08 核实）

- SPD 上游 **v4.0.0-beta 已于 2026-08-15 发布**（内部版本号 902），含史上最大新任务
  Vault Quest、新附魔、新美术。但 **beta 不公开源码**，所以 v3.3.8（2025-12 发布 /
  2026-03 补丁）仍是能拿到的最新公开源码，当前基线选择没问题。
- 隐忧：v4.0 正式版一旦放出源码，当前散落在 24 个文件里的改动会大规模冲突。
  建议把魔改逻辑收敛到少数 hook 点 + 配置驱动，降低未来 rebase 成本。
- 2026 年品类共识（多方来源一致）：从纯随机转向**可控的不可预测性**；
  **系统性深度优先于原始难度**（元素连锁、状态叠加）；跨局元叙事；
  替代胜利条件与玩家表达；实时数据驱动平衡。

### 内容基线（本项目 v3.3.8）

6 个职业 × 2 副职业（含 v3.0 新增 Cleric）、5 个 boss、26 层、16 个 Level 类。

### 魔改版的四个产品层缺口

1. **独占内容为零** —— 只做了减法（降难度）和打磨（修 bug、加测试），
   没有新职业 / 新物品 / 新 boss / 新机制，玩家没有理由选这一版。
2. **跨局进度无** —— SPD 原作者刻意不做。若要补，应做**解锁型**（新物品进掉落池、
   新起始装备、新天赋分支），**不要做数值型**。理由：2026 年玩家对数值型元进度
   反弹明显（ResetEra 2026-05 长贴），且解锁型与 SPD 的纯 roguelike 哲学兼容。
3. **叙事层为零** —— 世界观素材现成（Yendor 护符、矮人都市、恶魔大厅、六职业背景），
   但完全没有表达。NPC 对话 / 物品背景 / boss 台词是纯文本成本。
4. **系统交互无新增** —— SPD 的燃烧、中毒、冰冻、潮湿、电击基本各自孤立。
   加连锁（潮湿+电击=范围麻痹、油+火=爆燃、冰冻+物理=碎裂加伤）是**零美术成本**
   的差异化，最适合单人魔改。

### 新手友好方向性批评

当前做法是「降低难度」（200 血 + 敌方输出 ×0.64），属于下策；上策是「教学」。
2026 共识是让玩家**学会**而不是让玩家**不死**（Spelunky 2 的纯知识型进度即为例证）。
降到几乎死不了，玩家既学不到东西也拿不到成就感。

### 用户的独有优势（应重点发挥）

已有 headless 基础设施 + 561 个通过测试 = 具备**批量模拟跑数据驱动平衡**的能力，
这是多数独立开发者没有的。可产出：各职业胜率、死亡楼层分布、物品使用率热力图。
这既能形成差异化，也能反哺新手保护设计——用数据定位「新手到底死在哪一层」，
而不是靠拍脑袋调数值。
