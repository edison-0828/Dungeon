### 本轮新发现

**A. 老存档静默失效（中）**
`Tracker` 只在 `HeroClass.initHero()` → `BeginnerAid.beginRun()` 挂载，
而 `initHero` 仅由 Dungeon.java:288（新开局）调用，`Dungeon.loadGame()` 不调用。
结果：加此功能前创建的存档，读档后没有 Tracker → `isActive()` 恒 false →
全部新手辅助静默失效，连开局奖励窗口也不弹。
修法：读档路径补挂，或在 Hero.restoreFromBundle 里按 isNovice() 兜底。

**B. hint 的 shown 仍不存档（中）**
`shown` 是 static HashSet（BeginnerAid.java:58），`resetForRun()` 只在 `Dungeon.init()` 调用，
Tracker 的 Bundle 里没有它。读档后所有提示重新弹一遍。
讽刺点：Tracker 已经写了完整的序列化，唯独漏了 shown。把 shown 挪进 Tracker 即可。

**C. 十来个魔法数字零数据支撑（高，本轮重点）**
初始血量 30、ENEMY_DAMAGE 0.85、ENEMY_ACCURACY 0.85、SAFETY_SHIELD 8、
DOORWAY_SHIELD 3、FIRST_SURPRISE_DAMAGE 1.5、升级回血 30%、经验 ×1.5（6 级前）、
饥饿 ×1.75（1-5 层）、减怪 1 只（2-5 层）、前 5 层无诅咒——全部只有手感作依据。
用户已有 headless 基础设施，这些本该跑批量模拟得出。此建议昨天已提，尚未落地。

**D. 一次性机制无法培养习惯（设计层）**
12 个机制全是 one-shot，触发一次后玩家再无反馈。one-shot 只能「告知存在」，
不能「培养习惯」——玩家未必意识到「门口」才是关键。
建议改为衰减式（前 N 次给奖励）或持续小额收益，让玩家在几十次战斗中自然内化。

**E. 测试覆盖缺口**
8 个用例覆盖了 combat easing、safetyNet、surpriseReward、starterChoice、tracker 序列化、
completeFirstClear、potion desc，全部针对「防刷」这一核心风险，质量高。
未覆盖：`onHeroDefeatedEnemy`（门口护盾）、`expFactor`、`hungerDelayFactor`、
`skipSpawnCurses`、`onLevelUp`（回 30% 血）、`onGooChargeDodged`、老存档兼容性。

**F. 死亡归因缺失（产品层）**
新手死了不知道死于什么。SPD 死亡界面只有排名记录，没有伤害来源分布、
死亡楼层统计。这与用户的数据能力契合，是可做的差异化点。

## 第三轮：新增宠物的可行性勘察

用户问「新增一些新的宠物 UI 动画好做吗」。勘察结论：

### 关键事实：宠物系统是上游自带的，不是用户写的

`PetWhistle` / `PetAlly` / `PetBond` / `PetSprite` / `WndPetReplace`
均为上游 v3.3.8 原生（PetAlly 等最后改动 commit 41d2c3f9a）。
用户的两个 commit **完全没有碰过宠物相关文件**。

### 现有宠物系统结构

- `PetAlly.Appearance`（9 种）每种绑定一个 `Skill`：
  RAT→经验、ALBINO→生命、SNAKE→命中、CRAB→护甲、BAT→闪避、
  SLIME→回复、BEE→攻击、GNOLL→力量、SWARM→速度。
- `PetAlly.Quality`（4 档）：COMMON 1.00x / UNCOMMON 1.15x / RARE 1.30x /
  LEGENDARY 1.50x，各带 tint 与 `ItemSprite.Glowing`，抽取概率 45/30/18/7。
- `PetSprite.setup(appearance, quality)` 按外观 switch，复用现有怪物 PNG
  （rat / snake / crab / bat / slime / bee / gnoll / swarm），品质靠 tint 区分。
  即 9 × 4 = 36 种组合只用 9 套纹理。
- UI 侧目前只有 `WndPetReplace`（替换宠物窗口），无常驻 HUD 面板。

### 精灵与动画机制（决定美术门槛）

- 纹理是**独立 PNG 文件**，不是打包图集：`Assets.Sprites.RAT = "sprites/rat.png"`，
  加载用 `texture(...)` + `new TextureFilm(texture, w, h)` 按网格切帧。
  **加新资源只需放一个 PNG + Assets.java 加一行常量，不用跑 TexturePacker。**
- 各外观网格尺寸不一：16x15 / 12x11 / 16x16 / 15x15 / 14x12 / 16x16 / 12x15 / 16x16。
  参考图尺寸：rat 256x64、pet 128x16、bee 256x16。
- 一只宠物约 15-18 帧（idle 4 / run 5 / attack 5 / die 4），每帧 12-16px。

### 工作量判断

容易：复用现有纹理加外观（1-2 小时）、写帧序列（半小时）。
中等：特效与飘字（半天，工具箱现成：showStatusWithIcon / FloatingText / Emitter / Glowing）。
难：全新像素美术（取决于画功）、常驻 HUD 面板（移动端适配，数天起）。

### 两个需要提醒的约束

1. **9 个 Skill 已被 9 种外观占满**，加第 10 种外观必须先设计新 Skill，或让两种外观共用。
2. **新 UI 动画不能污染逻辑层**：HeadlessDungeon 刻意不初始化 `Gdx.gl`，
   任何把渲染混进逻辑的写法都会让现有 532 个测试崩掉。必须保持表现层与逻辑分离。

## 重要纠偏：宠物系统是用户自研，不是上游自带

前面「宠物系统全上游自带」的判断**是错的**，已向用户澄清。
用 `git cat-file -e 7b8b845a7:<path>` 验证：上游 v3.3.8 里
`items/PetWhistle.java`、`sprites/PetSprite.java`、`actors/mobs/npcs/PetAlly.java`
**均不存在**。整套宠物系统（Skill / Appearance / Quality 三枚举、PetBond、WndPetReplace、
开局三选一 PetOffer）都是用户在 commit 41d2c3f9a 里从零写的。
误判原因：只查了 `git log -1 -- <file>` 见到非用户 commit 就当成上游，
实际 41d2c3f9a 正是用户自己的提交。

## 第四轮：新增 SHEEP 宠物外观（已实施）

### 新增内容

外观 **SHEEP（绵羊）**，绑定**新 Skill `CRIT`（暴击率）**，复用 `sprites/sheep.png`
（64x16，16x15 网格 = 4 帧，索引 0-3，无越界风险），零美术成本。

### 改动的 6 个文件

1. `PetAlly.java` — Skill 枚举末尾加 `CRIT`；Appearance 枚举加 `SHEEP (Skill.CRIT)`。
   存档用 `name()` 字符串序列化，加枚举值不破坏老存档。
2. `PetSprite.java` — `setup()` switch 加 `case SHEEP`，新增 `setupSheep()`
   （idle 12 帧慢放、run 4 帧循环 1-2-3-2、attack 3-2-1-0、die 单帧）。
3. `PetBond.java` — 加 `public static float critMultiplier()`；
   `icon()` switch 加 `case CRIT: return BuffIndicator.COMBO`。
4. `HeroCombatStats.java` — `critChance()` 加 `+ bonusBps(PetBond.critMultiplier())`，
   照抄 `accuracyBonus()`/`evasionBonus()` 的既有范式。
   `bonusBps(m) = round((m-1) * 10_000)`，暴击单位是 bps（BASE 500 = 5%，上限 5000 = 50%）。
5. `actors.properties` / `actors_zh.properties` — 各加 3 条：
   `petally.sheep`、`petally.skill_crit`、`petally.bonus_crit`（百分比类用 `+%d%%` 转义）。
   注意宠物文案在 **actors** 文件里，不在 misc。
6. `PetBondTest.java` — `appearancePicksTheSkill` 补 SHEEP→CRIT 断言；
   新增 `sheepBoostsCrit`（CRAB 为基线 → 换 LEGENDARY SHEEP 后 critChance +1200 bps）。

### 既有约定（后续加外观照此办理）

- 宠物文案前缀固定为 `actors.mobs.npcs.petally.`，外观名 / `skill_xxx` / `bonus_xxx` 三段。
- 百分比加成用 `+%d%%`，flat 加成（STRENGTH / ARMOR）用 `+%d`。
- `PetBond` 里百分比类走 `multiplier(skill)`，flat 类走 `flat(skill)`；
  新百分比技能要在 PetBond 补一个 `public static float xxxMultiplier()` 并在 `icon()` 加 case。
- `PetBond.BASE_PERCENT = 0.08`，品质倍率 1.0 / 1.15 / 1.30 / 1.50。

### 遗留问题：GeneratorCategoryTest 状态污染（非本次引入）

`startingDeckComesFromItsOwnTemplate` 失败：
`WEP_T4 starts with [2,2,2,2,1,2,2] but its template is [2,2,2,2,2,2,2]`。
`git diff` 确认 Generator.java 无任何改动——是**运行时 probs 被改**，属于测试间状态污染。
根因：该用例注释自己写明「假设本 JVM 中没启动过游戏」，而测试集扩大后
（新增 PetBondTest / HeroCombatStatsTest / PetAllyDoorTest / ControlResistanceTest /
HeroLevelProgressionTest / EquipmentAffixesTest，它们都会 `HeadlessDungeon.startRun()`）
这个假设被打破了。

**修复难点**：不能在用例里调 `Generator.fullReset()`，因为 fullReset 本身就会
`probs = defaultProbs.clone()`，加进去测试必然恒过、彻底失去意义。
推荐方案：改为**源码级静态检查**——读取 Generator.java，正则匹配
`(\w+)\.probs\s*=\s*(\w+)\.defaultProbs`，断言左右标识符一致。
这样不依赖运行时状态与执行顺序，且精确保住「防手抄错 category 名」这一原始意图。
